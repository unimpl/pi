   1 # Session File Format
   2 
   3 Sessions are stored as JSONL (JSON Lines) files. Each line is a JSON object with a `type` field. Session entries form a tree structure via `id`/`parentId` fields, enabling in-place branching without creating new files.
   4 
   5 ## File Location
   6 
   7 ```
   8 ~/.pi/agent/sessions/--<path>--/<timestamp>_<session-id>.jsonl
   9 ```
  10 
  11 By default, `<session-id>` is a UUID. Callers can supply a custom ID through the SDK or `--session-id`. For `<path>`, Pi removes the leading path separator and replaces `/`, `\\`, and `:` with `-`.
  12 
  13 ## Deleting Sessions
  14 
  15 Sessions can be removed by deleting their `.jsonl` files under `~/.pi/agent/sessions/`.
  16 
  17 Pi also supports deleting sessions interactively from `/resume` (select a session and press `Ctrl+D`, then confirm). When available, pi uses the `trash` CLI to avoid permanent deletion.
  18 
  19 ## Session Version
  20 
  21 Sessions have a version field in the header:
  22 
  23 - **Version 1**: Linear entry sequence (legacy, auto-migrated on load)
  24 - **Version 2**: Tree structure with `id`/`parentId` linking
  25 - **Version 3**: Renamed `hookMessage` role to `custom` (extensions unification)
  26 
  27 Existing sessions are automatically migrated to the current version (v3) when loaded.
  28

  39 ## Message Types
  40 
  41 Session entries contain `AgentMessage` objects. Understanding these types is essential for parsing sessions and writing extensions.
  42 
  43 ### Content Blocks
  44 
  45 Messages contain arrays of typed content blocks:
  46 
  47 ```typescript
  48 interface TextContent {
  49   type: "text";
  50   text: string;
  51   textSignature?: string;
  52 }
  53 
  54 interface ImageContent {
  55   type: "image";
  56   data: string;      // base64 encoded
  57   mimeType: string;  // e.g., "image/jpeg", "image/png"
  58 }
  59 
  60 interface ThinkingContent {
  61   type: "thinking";
  62   thinking: string;
  63   thinkingSignature?: string;
  64   redacted?: boolean;
  65 }
  66 
  67 interface ToolCall {
  68   type: "toolCall";
  69   id: string;
  70   name: string;
  71   arguments: Record<string, any>;
  72   thoughtSignature?: string;
  73   namespace?: string;
  74 }
  75 ```

  77 ### Base Message Types (from pi-ai)
  78 
  79 ```typescript
  80 interface SystemMessage {
  81   role: "system";
  82   content: string | TextContent[];
  83   toolsAdded?: Tool[];
  84   toolsRemoved?: Array<{ name: string }>;
  85   timestamp: number;  // Unix ms
  86 }
  87 
  88 interface UserMessage {
  89   role: "user";
  90   content: string | (TextContent | ImageContent)[];
  91   timestamp: number;  // Unix ms
  92 }
  93 
  94 interface AssistantMessage {
  95   role: "assistant";
  96   content: (TextContent | ThinkingContent | ToolCall)[];
  97   api: string;
  98   provider: string;
  99   model: string;
 100   responseModel?: string;
 101   responseId?: string;
 102   providerThinkingLevel?: string;
 103   diagnostics?: AssistantMessageDiagnostic[];
 104   usage: Usage;
 105   stopReason: "pending" | "stop" | "length" | "toolUse" | "error" | "aborted" | "deferred";
 106   deferred?: DeferredHandle;
 107   errorMessage?: string;
 108   rawStopReason?: string;
 109   endTurn?: boolean;
 110   timestamp: number;
 111 }
 112 
 113 interface ToolResultMessage {
 114   role: "toolResult";
 115   toolCallId: string;
 116   toolName: string;
 117   content: (TextContent | ImageContent)[];
 118   details?: any;      // Tool-specific metadata
 119   usage?: Usage;      // Nested LLM work performed by the tool
 120   isError: boolean;
 121   timestamp: number;
 122 }
 123 
 124 interface Usage {
 125   input: number;
 126   output: number;
 127   cacheRead: number;
 128   cacheWrite: number;
 129   cacheWrite1h?: number;
 130   reasoning?: number;
 131   totalTokens: number;
 132   cost: {
 133     input: number;
 134     output: number;
 135     cacheRead: number;
 136     cacheWrite: number;
 137     total: number;
 138   };
 139 }
 140 ```
 141 
 142 `"pending"` is reserved for partial messages in streaming events. Terminal events replace it with a completion reason before Pi persists the assistant message, so `"pending"` should never appear in session JSONL. `"deferred"` is a terminal reason for a provider response that will complete later; its `deferred` handle contains the provider data needed to retrieve that response.

 197 ## Entry Base
 198 
 199 All entries (except `SessionHeader`) extend `SessionEntryBase`:
 200 
 201 ```typescript
 202 interface SessionEntryBase {
 203   type: string;
 204   id: string;           // Usually an 8-char hex ID; may fall back to a full UUID
 205   parentId: string | null;  // Parent entry ID (null for a root entry)
 206   timestamp: string;    // ISO timestamp
 207 }
 208 ```
 209 
 210 ## Entry Types
 211 
 212 ### SessionHeader
 213 
 214 First line of the file. Metadata only, not part of the tree (no `id`/`parentId`).
 215 
 216 ```json
 217 {"type":"session","version":3,"id":"uuid","timestamp":"2024-12-03T14:00:00.000Z","cwd":"/path/to/project"}
 218 ```
 219 
 220 For sessions with a parent (created via `/fork`, `/clone`, or `newSession({ parentSession })`):
 221 
 222 ```json
 223 {"type":"session","version":3,"id":"uuid","timestamp":"2024-12-03T14:00:00.000Z","cwd":"/path/to/project","parentSession":"/path/to/original/session.jsonl"}
 224 ```
 225 
 226 ### SessionMessageEntry
 227 
 228 A message in the conversation. The `message` field contains an `AgentMessage`. System messages carry the prompt and tool loadout: the first request of a session persists one with every prompt section and tool declaration, and later changes persist as system messages that patch `sections` by name (`null` removes one) and list `toolsAdded`/`toolsRemoved`. Replaying them in order yields the current prompt and tools; there is no separate prompt state entry.
 229 
 230 ```json
 231 {"type":"message","id":"a0b1c2d3","parentId":null,"timestamp":"2024-12-03T14:00:00.000Z","message":{"role":"system","content":"","sections":{"preamble":"You are an expert coding assistant...","tools":"<tools>\n- read: ...\n</tools>","cwd":"/project"},"toolsAdded":[{"name":"read","description":"...","parameters":{}}],"timestamp":1733234400000}}
 232 {"type":"message","id":"d4e5f6g7","parentId":"c3d4e5f6","timestamp":"2024-12-03T14:04:00.000Z","message":{"role":"system","content":"","sections":{"skills":"<skills>...</skills>"},"toolsRemoved":[{"name":"write"}],"timestamp":1733234640000}}
 233 ```
 234 
 235 Sessions created before system messages existed have no leading system message; the first request declares the current prompt as a later system message, which replays the same way.
 236 
 237 ```json
 238 {"type":"message","id":"a1b2c3d4","parentId":"prev1234","timestamp":"2024-12-03T14:00:01.000Z","message":{"role":"user","content":"Hello","timestamp":1733234401000}}
 239 {"type":"message","id":"b2c3d4e5","parentId":"a1b2c3d4","timestamp":"2024-12-03T14:00:02.000Z","message":{"role":"assistant","content":[{"type":"text","text":"Hi!"}],"api":"anthropic-messages","provider":"anthropic","model":"claude-sonnet-4-5","usage":{...},"stopReason":"stop","timestamp":1733234402000}}
 240 {"type":"message","id":"c3d4e5f6","parentId":"b2c3d4e5","timestamp":"2024-12-03T14:00:03.000Z","message":{"role":"toolResult","toolCallId":"call_123","toolName":"bash","content":[{"type":"text","text":"output"}],"isError":false,"timestamp":1733234403000}}
 241 ```
 242 
 243 ### ModelChangeEntry
 244 
 245 Emitted when the user switches models mid-session.
 246 
 247 ```json
 248 {"type":"model_change","id":"d4e5f6g7","parentId":"c3d4e5f6","timestamp":"2024-12-03T14:05:00.000Z","provider":"openai","modelId":"gpt-4o"}
 249 ```
 250 
 251 ### ThinkingLevelChangeEntry
 252 
 253 Emitted when the user changes the thinking/reasoning level.
 254 
 255 ```json
 256 {"type":"thinking_level_change","id":"e5f6g7h8","parentId":"d4e5f6g7","timestamp":"2024-12-03T14:06:00.000Z","thinkingLevel":"high"}
 257 ```
 258 
 259 ### CompactionEntry
 260 
 261 Created when context is compacted. Stores a summary of earlier messages and a complete system prompt/tool checkpoint.
 262 
 263 ```json
 264 {"type":"compaction","id":"f6g7h8i9","parentId":"e5f6g7h8","timestamp":"2024-12-03T14:10:00.000Z","summary":"User discussed X, Y, Z...","firstKeptEntryId":"c3d4e5f6","tokensBefore":50000,"systemMessage":{"role":"system","content":"You are a coding assistant.","toolsAdded":[],"timestamp":1733235000000}}
 265 ```
 266 
 267 `firstKeptEntryId` is required. It identifies the first entry retained from before the compaction entry. When rebuilding context, Pi replaces older summarized entries with the compaction summary and keeps the range beginning at this entry.
 268 
 269 Optional fields:
 270 - `systemMessage`: The replayed prompt sections and tool declarations at the compaction boundary; it becomes the leading system message of the compacted context, and system messages among the kept entries are dropped in its favor. It is absent on older session entries.
 271 - `usage`: LLM usage from generating the summary; included in session token and cost totals
 272 - `details`: Implementation-specific data (e.g., `{ readFiles: string[], modifiedFiles: string[] }` for default, or custom data for extensions)
 273 - `fromHook`: `true` if generated by an extension, `false`/`undefined` if pi-generated (legacy field name)
 274 
 275 ### BranchSummaryEntry
 276 
 277 Created when switching branches via `/tree` with an LLM generated summary of the left branch up to the common ancestor. Captures context from the abandoned path.
 278 
 279 ```json
 280 {"type":"branch_summary","id":"g7h8i9j0","parentId":"a1b2c3d4","timestamp":"2024-12-03T14:15:00.000Z","fromId":"f6g7h8i9","summary":"Branch explored approach A..."}
 281 ```
 282 
 283 `parentId` is the entry from which the new branch continues. `fromId` is the previous leaf whose abandoned path was summarized.
 284 
 285 Optional fields:
 286 - `usage`: LLM usage from generating the summary; included in session token and cost totals
 287 - `details`: File tracking data (`{ readFiles: string[], modifiedFiles: string[] }`) for default, or custom data for extensions
 288 - `fromHook`: `true` if generated by an extension, `false`/`undefined` if pi-generated (legacy field name)
 289 
 290 ### CustomEntry
 291 
 292 Extension state persistence. Does NOT participate in LLM context.
 293 
 294 ```json
 295 {"type":"custom","id":"h8i9j0k1","parentId":"g7h8i9j0","timestamp":"2024-12-03T14:20:00.000Z","customType":"my-extension","data":{"count":42}}
 296 ```
 297 
 298 Use `customType` to identify your extension's entries on reload. Interactive mode can render custom entries via `pi.registerEntryRenderer(customType, renderer)`, but they still do not participate in LLM context.
 299 
 300 ### CustomMessageEntry
 301 
 302 Extension-injected messages that DO participate in LLM context.
 303 
 304 ```json
 305 {"type":"custom_message","id":"i9j0k1l2","parentId":"h8i9j0k1","timestamp":"2024-12-03T14:25:00.000Z","customType":"my-extension","content":"Injected context...","display":true}
 306 ```
 307 
 308 Fields:
 309 - `content`: String or `(TextContent | ImageContent)[]` (same as UserMessage)
 310 - `display`: `true` = show in TUI with distinct styling, `false` = hidden
 311 - `details`: Optional extension-specific metadata (not sent to LLM)
 312 
 313 ### LabelEntry
 314 
 315 User-defined bookmark/marker on an entry.
 316 
 317 ```json
 318 {"type":"label","id":"j0k1l2m3","parentId":"i9j0k1l2","timestamp":"2024-12-03T14:30:00.000Z","targetId":"a1b2c3d4","label":"checkpoint-1"}
 319 ```
 320 
 321 Set `label` to `undefined` to clear a label.
 322 
 323 ### SessionInfoEntry
 324 
 325 Session metadata (e.g., user-defined display name). Set via `/name`, `--name` / `-n`, or `pi.setSessionName()` in extensions.
 326 
 327 ```json
 328 {"type":"session_info","id":"k1l2m3n4","parentId":"j0k1l2m3","timestamp":"2024-12-03T14:35:00.000Z","name":"Refactor auth module"}
 329 ```
 330 
 331 The session name is displayed in the session selector (`/resume`) instead of the first message when set.
 332 
 333 ## Tree Structure
 334 
 335 Entries normally form one tree, but navigation APIs can create multiple roots:
 336 - A root entry has `parentId: null`; the first entry is initially the root
 337 - Each non-root entry points to its parent via `parentId`
 338 - Branching creates new children from an earlier entry
 339 - The "leaf" is the current position in the tree
 340 - Calling `resetLeaf()` or `branchWithSummary(null, ...)` allows a later entry to become another root
 341 
 342 ```
 343 [user msg] ─── [assistant] ─── [user msg] ─── [assistant] ─┬─ [user msg] ← current leaf
 344                                                             │
 345                                                             └─ [branch_summary] ─── [user msg] ← alternate branch
 346 ```
 347 
 348 ## Context Building
 349 
 350 `buildContextEntries()` walks from the current leaf to the root, producing the active entry list while honoring compaction:
 351 
 352 1. Collects all entries on the path
 353 2. If one or more `CompactionEntry` values are on the path, uses the latest one:
 354    - Includes the compaction entry first
 355    - Includes non-system entries from `firstKeptEntryId` up to, but not including, the compaction entry
 356    - Includes entries after the compaction entry
 357 3. Preserves non-message entries in the selected range so interactive mode can render them
 358 
 359 `buildSessionContext()` builds on that entry list to produce the message list for the LLM:
 360 
 361 1. Extracts current model and thinking level settings from the full path
 362 2. Converts selected entries to messages:
 363    - `message` -> stored `AgentMessage`
 364    - `compaction` -> complete system checkpoint followed by `compactionSummary`
 365    - `branch_summary` -> `branchSummary`
 366    - `custom_message` -> `CustomMessage`
 367    - `custom` -> no context message
 368 
 369 The compaction summary replaces entries before `firstKeptEntryId`. Pre-compaction system messages are folded into the complete checkpoint rather than replayed from the retained range. Retained non-system entries and all entries after the compaction remain available to the LLM.
 370 
 371 ## Parsing Example
 372 
 373 ```typescript
 374 import { readFileSync } from "fs";
 375 
 376 const lines = readFileSync("session.jsonl", "utf8").trim().split("\n");
 377 
 378 for (const line of lines) {
 379   const entry = JSON.parse(line);
 380 
 381   switch (entry.type) {
 382     case "session":
 383       console.log(`Session v${entry.version ?? 1}: ${entry.id}`);
 384       break;
 385     case "message":
 386       console.log(`[${entry.id}] ${entry.message.role}: ${JSON.stringify(entry.message.content)}`);
 387       break;
 388     case "compaction":
 389       console.log(`[${entry.id}] Compaction: ${entry.tokensBefore} tokens summarized`);
 390       break;
 391     case "branch_summary":
 392       console.log(`[${entry.id}] Branch from ${entry.fromId}`);
 393       break;
 394     case "custom":
 395       console.log(`[${entry.id}] Custom (${entry.customType}): ${JSON.stringify(entry.data)}`);
 396       break;
 397     case "custom_message":
 398       console.log(`[${entry.id}] Extension message (${entry.customType}): ${entry.content}`);
 399       break;
 400     case "label":
 401       console.log(`[${entry.id}] Label "${entry.label}" on ${entry.targetId}`);
 402       break;
 403     case "model_change":
 404       console.log(`[${entry.id}] Model: ${entry.provider}/${entry.modelId}`);
 405       break;
 406     case "thinking_level_change":
 407       console.log(`[${entry.id}] Thinking: ${entry.thinkingLevel}`);
 408       break;
 409   }
 410 }
 411 ```

 413 ## SessionManager API
 414 
 415 Key methods for working with sessions programmatically.
 416 
 417 ### Static Creation Methods
 418 - `SessionManager.create(cwd, sessionDir?, options?)` - New session; `options` can set `id` and `parentSession`
 419 - `SessionManager.open(path, sessionDir?, cwdOverride?)` - Open existing session file
 420 - `SessionManager.continueRecent(cwd, sessionDir?)` - Continue most recent or create new
 421 - `SessionManager.inMemory(cwd?, options?, entries?)` - No file persistence, optionally initialized from entries
 422 - `SessionManager.forkFrom(sourcePath, targetCwd, sessionDir?, options?)` - Fork session from another project
 423 
 424 ### Static Listing Methods
 425 - `SessionManager.list(cwd, sessionDir?, onProgress?)` - List sessions for a directory
 426 - `SessionManager.listAll(onProgress?)` - List all sessions across all projects
 427 - `SessionManager.listAll(sessionDir?, onProgress?)` - List sessions from a custom session root
 428 
 429 ### Instance Methods - Session Management
 430 - `newSession(options?)` - Start a new session (options: `{ id?: string, parentSession?: string }`)
 431 - `setSessionFile(path)` - Switch to a different session file
 432 - `createBranchedSession(leafId)` - Extract branch to new session file
 433 
 434 ### Instance Methods - Appending (all return entry ID)
 435 - `appendMessage(message)` - Add message
 436 - `appendThinkingLevelChange(level)` - Record thinking change
 437 - `appendModelChange(provider, modelId)` - Record model change
 438 - `appendCompaction(summary, firstKeptEntryId, tokensBefore, details?, fromHook?, usage?)` - Add compaction
 439 - `appendCustomEntry(customType, data?)` - Extension state (not in context)
 440 - `appendSessionInfo(name)` - Set session display name
 441 - `appendCustomMessageEntry(customType, content, display, details?)` - Extension message (in context)
 442 - `appendLabelChange(targetId, label)` - Set/clear label
 443 
 444 ### Instance Methods - Tree Navigation
 445 - `getLeafId()` - Current position
 446 - `getLeafEntry()` - Get current leaf entry
 447 - `getEntry(id)` - Get entry by ID
 448 - `getBranch(fromId?)` - Walk from entry to root
 449 - `getTree()` - Get full tree structure
 450 - `getChildren(parentId)` - Get direct children
 451 - `getLabel(id)` - Get label for entry
 452 - `branch(entryId)` - Move leaf to earlier entry
 453 - `resetLeaf()` - Reset leaf to null (before any entries)
 454 - `branchWithSummary(entryId, summary, details?, fromHook?, usage?)` - Branch with context summary; `entryId` may be `null` to branch from the root
 455 
 456 ### Instance Methods - Context & Info
 457 - `buildContextEntries()` - Get active branch entries with compaction applied
 458 - `buildSessionContext()` - Get messages, thinkingLevel, and model for LLM
 459 - `getEntries()` - All entries (excluding header)
 460 - `getHeader()` - Session header metadata
 461 - `getSessionName()` - Get display name from latest session_info entry
 462 - `getCwd()` - Working directory
 463 - `getSessionDir()` - Session storage directory
 464 - `getSessionId()` - Session UUID
 465 - `getSessionFile()` - Session file path (undefined for in-memory)
 466 - `isPersisted()` - Whether session is saved to disk
