术语与阅读路线

遇到陌生名词时回到这里。先理解角色和时间边界，再追踪具体实现。

术语表

Agent
模型与工具执行构成的反馈系统；在本书中以 pi 的具体运行时为准。 阅读相关章节
AgentSession
coding-agent 的应用协调层，连接 Agent、持久会话、设置、扩展、压缩和重试，并向不同界面提供统一操作。 阅读相关章节
SessionManager
当前 coding-agent 的持久会话管理器，保存带父子关系的消息和状态条目。 阅读相关章节
Harness
围绕模型执行的宿主设施，管理工具、上下文与生命周期；新 Harness 的范围比基础循环更广。 阅读相关章节
Provider / API
服务来源 / 协议实现。二者不是同一个维度。 阅读相关章节
Transcript
按顺序组织的消息记录；其中的 system 更新也承载规则和工具变化。 阅读相关章节
Context
当前操作的上下文；模型上下文与 Chord 的取消/调用上下文是不同概念。 阅读相关章节
Tool call / Tool result
模型提出的结构化请求 / 程序执行后返回的反馈，通过调用 ID 关联。 阅读相关章节
Token / Context window
模型输入输出的计量单位 / 请求可以容纳的上下文容量。 阅读相关章节
Turn / Run
低层 turn 是一次模型响应及其工具批次；一次 run 可有多个 turn。压缩模块的轮次定义不同。 阅读相关章节
Steering / Follow-up
下一轮介入当前工作 / 当前工作本来要结束时追加任务。 阅读相关章节
Compaction
用摘要与近期消息构建更小的模型上下文，不等于删除完整会话。 阅读相关章节
Promise / AsyncIterable
未来完成的结果 / 可按到达顺序异步迭代的数据源。 阅读相关章节
Schema
运行时可以验证的数据结构规则，与擦除后的 TypeScript 类型有别。 阅读相关章节
Facet
插件在某个运行环境中的组成部分，由宿主装配依赖与生命周期。 阅读相关章节
Attachment
某个展示端与会话的一次挂接身份，用于拒绝过期路由。 阅读相关章节
Projection
从记录中构建用于特定目的的视图，例如当前路径的模型上下文。 阅读相关章节
Side effect
改变外部世界的操作，例如写文件；取消或重试需要考虑其真实完成状态。 阅读相关章节

三遍阅读源码

  1. 第一遍：数据与边界。先看 agent/types.ts 的 StreamFn、AgentTool、AgentEvent，再看 ai/types.ts 的消息角色。只回答“数据由谁提供、流向哪里”。
  2. 第二遍：执行与结算。读 agent-loop.ts 的 runLoop、streamAssistantResponse、executeToolCalls，再读 agent.ts 的 processEvents 与 finishRun。把每个 await 前后发生的事情串起来。
  3. 第三遍：产品与演进。读 SDK 装配、messages.ts 转换、compaction 切点与摘要，再读运行时替换。之后才进入 Chord 和新存储方案，并核对公开导出与设计文档的差距。

设计原则索引

  • 变化在边界收敛：类型、转换与协议适配。
  • 区分事实、视图与过程：会话、上下文、运行状态。
  • 把时间顺序写成契约：并发、事件和结算。
  • 保守处理副作用：不完整参数、取消与恢复。
  • 可扩展且责任可见：注入、工具和生命周期。
