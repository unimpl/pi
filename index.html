读懂 Pi，
理解 Agent 的设计。

一本给系统开发者的源码设计读本。

你已有 Go、Rust、C++ 的经验。我们从熟悉的接口、状态和 I/O 出发，沿一次请求进入 pi：不仅看它如何工作，也看它为什么这样组织，以及这些选择的代价。

开始阅读第一章先看架构地图

先理解，再判断。

不需要先学完整的 JavaScript，不安排实现练习。每章先说明设计动机、行业常见方案和实现取舍，再回到 Pi 的代码证据。全部图表由 Mermaid 描述并预渲染，离线打开也能阅读。

当前实现以本地源码和公开导出为证据。

行业参照用于比较常见方案，不作为框架排名。

实现判断明确必须先设计、按需加入和暂时忽略的部分。

十章，一条阅读路径

第一至七章是 Agent 与 Harness 的核心；基础设施章按需了解；第九章把代码归纳成设计判断；第十章从发版记录回看功能演进。

01

先认识 Pi 的核心对象

Session 保存工作，Agent 执行；一次 run 由一个或多个 turn 组成。

基础02

沿着职责，而非目录理解架构

把模型协议、执行机制与产品策略分开。

基础03

一次请求，究竟经过了什么

跟随消息，而不是跟随屏幕上的文字。

核心04

控制权必须留在运行时

循环、队列与事件共同定义“什么时候能继续”。

核心05

从一个模型调用，推导 Pi 的类型

每个类型都应回答一个具体问题；最小实现不必复制完整的多供应商体系。

核心06

工具是能力，也是边界

从声明到副作用，中间不能少掉执行规则。

核心07

记住历史，不等于发送全部历史

会话是记录，上下文是投影，运行状态是此刻。

核心08

从本地助手走向可组合系统

先问需要跨越什么边界，再决定引入什么基础设施。

进阶09

把实现读成设计判断

学习可解释的取舍，而不是收集架构口号。

综合10

从发版记录理解功能演进

从全部发版记录中识别能力边界、迁移成本与实验方向。

演进

让阅读有一个落点

贯穿案例是“读取 README.md 并解释项目”。请求循环、工具失败分支和上下文压缩都以 Mermaid 图和文字轨迹解释，不运行真实工具，也不请求模型。

第一遍只读“本章先抓什么”和图解，第二遍读正文，第三遍展开源码证据。读完后应能判断自己的 Agent 或 Harness 必须实现哪些边界，哪些复杂度可以推迟。
